\subsection{Privacy and distribution controls}
\begin{itemize}
\item \textbf{Least privilege.} Explain SMS, location, notifications and microphone permissions individually. Request background location only for the enabled journey. Start microphone/location services only in permitted states; surface unavailable features.
\item \textbf{Device protection.} Keep the PIN local; encrypt evidence with AES-GCM; protect keys, block screenshots by default and disable Android backup. Export is explicit and decrypted temporary files are removed.
\item \textbf{Server protection.} RLS on every exposed table; validate JWTs and ownership; restrict tracker RPC fields. Never ship Groq, Telegram or service-role credentials to app/web clients. Redact token, phone, GPS and evidence data from logs.
\item \textbf{Sharing and retention.} Treat the tracker URL as a bearer secret: HTTPS, no indexing or referrer leakage, and no evidence in the response. The current SQL expires resolved links after 24 h; acceptance must also cover stale active incidents and user-initiated revocation before wider rollout.
\item \textbf{Release policy.} Google Play restricts SMS permissions. Physical-safety alerts are an exception category subject to declaration and review, not automatic approval. Validate accessibility/background permissions and current target-API requirements before submission. \source{3}{https://support.google.com/googleplay/android-developer/answer/10208820}
\end{itemize}
