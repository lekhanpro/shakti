\section{Deployment, maintenance and handover}

\subsection{Release in a controlled sequence}
\begin{enumerate}
\item \textbf{Prepare environments.} Separate development, staging and pilot projects. Configure app \code{SUPABASE\_URL}, \code{SUPABASE\_ANON\_KEY} and \code{TRACK\_BASE\_URL}; set matching public web values. Keep provider secrets and signing material in restricted secret stores, never source control.
\item \textbf{Deploy the backend.} Take a backup; test migrations on staging, apply the versioned schema and run SQL/RLS tests. Deploy \code{ai-guard}, \code{emergency-dispatch} and \code{guardian-invite}; configure secrets, authentication redirects and Telegram chat access. Prove that unauthorised requests fail. \source{5}{https://supabase.com/docs/guides/functions/deploy}
\item \textbf{Publish the HTTPS website.} Deploy the pinned Next.js build to the approved host, configure DNS/TLS and the app's matching tracker origin. Test a real incident token, expiration, polling and unavailable-backend states; publish the correct release download link.
\item \textbf{Build and sign Android.} CI runs analysis, coverage, Deno/SQL checks and web tests/build. Wire all production providers, then build a signed release APK and AAB using protected keys. Preserve the signing identity; attach version, checksum, change notes and known device limits to the release.
\item \textbf{Run a staged pilot.} Install on designated phones with consented test contacts. Demonstrate SMS with internet off, failure states, cloud recovery, guardian tracking, encrypted evidence and PIN resolution. Test alerts must be clearly identified; record results before inviting broader use.
\item \textbf{Approve and distribute.} Begin with the signed pilot APK through a controlled HTTPS download. Submit the AAB to Google Play only after permission declarations, privacy/data-safety materials and current store requirements are satisfied. Tag approved releases \code{vX.Y.Z}; expand the pilot only after critical failures are resolved.
\end{enumerate}

\begin{cautionbox}[title=Rollback and outage response]
Keep the last known-good app and web/edge release available. For Android, rebuild the previous stable code with a higher version code and the same signing key. Roll back web/edge versions independently; prefer forward-compatible database fixes. Restore a tested database backup only through a documented recovery procedure. During a cloud outage, explain the degraded state and preserve the local SOS path.
\end{cautionbox}

\subsection{Handover package and references}
Deliver the source/lockfiles, migration history, redacted configuration examples, service-adapter map, access-ownership register, device QA results, signed build/checksum, user guide, backup/restore instructions and community presentation. Keep secrets and private test data outside the package.
