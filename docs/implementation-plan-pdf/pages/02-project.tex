\section{Project purpose and delivery scope}

Shakti is an \term{offline-first Android personal-safety network} for women, students and staff travelling alone. A user can raise an emergency without navigating several screens; trusted family, friends or campus security receive an actionable alert. The project combines a phone app, a cloud coordination layer and a browser tracker, so guardians do not have to install another app.

\begin{keyfact}[title=Community outcome]
Reduce the steps between recognising danger and requesting help. Provide a location when available, make the result of each alert channel visible, and preserve an incident record. Shakti supports human response; it does not promise rescue, continuous connectivity or a certified safe route.
\end{keyfact}

\subsection{What works with each connection state}
\begin{itemize}
\item \textbf{No internet, cellular service available:} local incident storage, carrier SMS, PIN, fake call and permitted device tools remain usable. SMS requires a SIM, signal, permission and carrier allowance; it is not an internet service.
\item \textbf{Internet available:} upload queued incidents and breadcrumbs; send Telegram alerts; load the guardian tracker, remote map/routing data and AI responses.
\item \textbf{No cellular service and no internet:} keep the local record and available device tools. Show that messages have not been sent; retry cloud work after reconnecting. Offline maps require previously cached data.
\end{itemize}

\subsection{Definition of success}
All core features must pass integration tests on real devices. Targets are \textbf{under 1.2 s from countdown end to SMS handoff}, \textbf{under 1.5 s cold start}, and \textbf{at least 80\% line coverage of domain/data code}. Measure these separately from carrier delivery time. Battery use and lock-screen behaviour require hardware evidence before release (section~\ref{sec:verification}).
